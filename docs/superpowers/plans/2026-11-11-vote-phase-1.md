# The vote, phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Devcon demo vote into "the vote": no Devcon left in the code, test rounds (paper
codes, Sepolia) still working, and a real round where only holders of the private voting badge vote
on mainnet, reached from a Vote menu item, with the live result on the front page.

**Architecture:** One round at a time, described by `shared/vote/manifest-data.ts`, now with
`kind: "test" | "real"` and an optional `badge`. Server and client read the chain from the
manifest's `chainId`. Test rounds keep the code → mint → ballot flow. The real round enters through
the signed-in account's voting badges (`/api/vote/mine` → `ids`). The results, extracted from
`routes/devcon.tsx`, renders on `/` for a real round and on `/vote` (voters and admins) for a test
round.

**Tech Stack:** React Router 7 (framework mode), TanStack Query, viem/wagmi, Hono on Deno, Deno KV,
vitest (`deno run -A npm:vitest run`), `deno test` for `api/` and `scripts/`.

**Spec:** `docs/superpowers/specs/2026-11-11-vote-design.md` (phase 1 only; phase 2, the quiet
ending, gets its own plan).

## Global Constraints

- No "devcon"/"DevCon"/"Devcon" left in `app/`, `api/`, `shared/`, `scripts/`, `deno.json`,
  `.gitignore`, `.env.example`, except docs under `docs/` and `comms/` (kept as history) and
  `vote/test/DevconSchedule.t.sol` (contract tests are out of scope).
- Voting badge = `REVIEW_BADGE_CONTRACT` (`0x3B49f45EC8796F64feBB1Ae0f5661791845ce35C`, mainnet).
  `BADGE_CONTRACT` (the public ETHSecurity badge) never gives a ballot.
- Routes: `/vote`, `/vote/ballot`, `/vote/:code`; API prefix `/api/vote`. No `/devcon` redirects.
- KV prefix `["vote", …]`; env `VOTE_RELAYER_KEY`, `VOTE_ISSUER_KEY`.
- Relays per badge: 20 in test rounds, 5 in the real round. Gas drip, code lookup and claim exist
  only in test rounds (real round: 404, code `off`).
- Copy: test rounds "Test vote", real round "TheDAO vote"; kicker on the ballot "Test vote · Badge
  #n" / "TheDAO vote · Badge #n".
- Keep the uncommitted schedule changes in the deploy script and its test, and the uncommitted
  `vote/` docs and reference changes, untouched.
- Prose style: the repo's comments and copy are plain, short sentences.

## Review Focus

1. A wallet holding only the public ETHSecurity badge, in a real round: no Vote item, `/vote/ballot`
   says no voting badge, `POST /api/vote/ballot` for any token it doesn't own is refused. (Task 3
   and Task 5 tests.)
2. A real-round `ballot` call whose signer owns the token on the review badge contract but the API
   read `ownerOf` from the ballots contract (which has no tokens in external mode) → must verify
   against `badge`. (Task 3 test.)
3. Signed-out visitor or non-voter opening `/vote` during a test round: sees the "This page is for
   voters" panel, never the tally. (Task 6 test.)
4. No round deployed (`contract` all zeros): no Vote item, `/` is the normal board, `/vote*` say
   there's no vote right now, API 503 `off`. (Tasks 3, 5, 6.)
5. A badge holder with two voting badges: `/vote/ballot` shows a picker, and `?badge=40` opens badge
   40's ballot; an id not in `ids` falls back to the first. (Task 4 test.)
